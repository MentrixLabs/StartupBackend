На основе предоставленного технического задания (ТЗ) и анализа современных подходов к разработке веб-интерфейсов, я подготовил для вас детальный план создания Frontend-части (сайта) для стартап-проекта "Proskladai".

Сайт должен стать центральным элементом экосистемы, предоставляя удобный веб-интерфейс для пользователей и администраторов, дополняя функциональность Telegram-бота.

### 1. Назначение и основные функции сайта

Сайт будет выполнять две ключевые роли:

1.  **Публичный Landing Page (Сайт-визитка)**: Представление стартап-проекта, его возможностей и преимуществ для привлечения новых пользователей.
2.  **Личный кабинет пользователя (Web-интерфейс)**: Расширенный функционал для работы с товарами, который дублирует и дополняет возможности Telegram-бота. Это позволит пользователям выбирать наиболее удобный способ взаимодействия.

**Основные функции личного кабинета:**
*   **Управление профилем**: Регистрация, аутентификация, просмотр и редактирование данных.
*   **Управление товарами**: Просмотр списка загруженных карточек товаров, добавление новых, редактирование и удаление.
*   **Генерация SEO-оптимизации**: Интерфейс для запуска генерации текстового контента для карточки товара на основе моделей машинного обучения (DeepSeek/ChatGPT API).
*   **Поиск и управление инфографикой**: Возможность инициировать поиск релевантных изображений по товару, просматривать результаты (от 1 до 20 изображений) и управлять ими.
*   **Формирование отчетов**: Просмотр и скачивание отчетов по результатам комплексной оптимизации товаров.
*   **Аналитика и дашборд**: Визуализация ключевых метрик (количество обработанных товаров, сгенерированных SEO-текстов, найденных изображений и т.д.).

### 2. Рекомендуемый стек технологий

Выбор технологического стека должен обеспечивать высокую производительность, удобство разработки и масштабируемость.

*   **Фреймворк**: **React 19** с **TypeScript**.
    *   **Обоснование**: React является лидирующим и наиболее востребованным фреймворком, обеспечивающим гибкость, масштабируемость и огромное сообщество. TypeScript повышает надежность кода за счет строгой типизации.
*   **Сборщик и инструменты разработки**: **Vite**.
    *   **Обоснование**: Обеспечивает молниеносную скорость сборки и разработки, что критично для современных SPA (Single Page Applications).
*   **Язык стилей**: **Tailwind CSS**.
    *   **Обоснование**: Позволяет быстро создавать современный, адаптивный и кастомизируемый дизайн без необходимости писать CSS с нуля.
*   **UI-библиотека компонентов**: **shadcn/ui**.
    *   **Обоснование**: Предоставляет набор доступных, переиспользуемых и стилизуемых компонентов, что значительно ускоряет разработку и обеспечивает единый стиль интерфейса.
*   **Маршрутизация**: **React Router v7**.
    *   **Обоснование**: Стандартное решение для навигации в React-приложениях.
*   **HTTP-клиент**: **Axios**.
    *   **Обоснование**: Упрощает выполнение HTTP-запросов к бэкенду (FastAPI) и обработку ответов.
*   **Анимации**: **Framer Motion**.
    *   **Обоснование**: Позволяет создавать плавные и привлекательные анимации, улучшая пользовательский опыт.
*   **Визуализация данных**: **Chart.js** или **Recharts**.
    *   **Обоснование**: Для создания интерактивных графиков и диаграмм на дашбордах.
*   **Сборка и деплой**:
    *   **Docker**: Для контейнеризации приложения и обеспечения согласованности сред разработки, тестирования и продакшна.
    *   **Vercel / Netlify**: Для быстрого и удобного деплоя статичных файлов и SPA.

### 4. Интеграция с Backend и Telegram-ботом

Сайт будет взаимодействовать с существующей серверной частью на **Python (FastAPI)** через **REST API**.

*   **API-клиент**: В папке `src/api/` будут описаны все функции для отправки запросов к эндпоинтам бэкенда (генерация SEO, поиск инфографики, управление товарами и т.д.).
*   **Аутентификация**: Будет реализована через **JWT-токены**. После успешного входа токен будет сохраняться, например, в `httpOnly` cookie или `localStorage` и автоматически добавляться в заголовок `Authorization` для всех защищенных запросов.
*   **Проксирование**: В боевой среде рекомендуется настроить обратный прокси (например, **Caddy** или **Nginx**) для раздачи статики фронтенда и проксирования запросов к `/api/*` на бэкенд-сервер. Это упрощает настройку CORS и повышает безопасность.

### 5. Требования к дизайну и пользовательскому опыту (UX/UI)

*   **Адаптивность**: Сайт должен корректно отображаться на всех типах устройств: от настольных ПК до мобильных телефонов.
*   **Скорость загрузки**: Использование Vite и оптимизация ресурсов (ленивая загрузка, сжатие изображений) обеспечат быструю загрузку страниц.
*   **Интуитивность**: Интерфейс должен быть понятным и не требовать специального обучения. Ключевые действия (добавление товара, генерация SEO) должны быть выделены визуально.
*   **Единый стиль**: Использование Tailwind CSS и shadcn/ui гарантирует современный, чистый и консистентный внешний вид, соответствующий бренду стартапа.

### 6. Этапы разработки Frontend

Этапы синхронизированы с этапами разработки бэкенда из ТЗ:

*   **Этап 1 (Параллельно с этапом 1 бэкенда)**: Разработка архитектуры фронтенда, выбор стека, создание макетов (UI/UX дизайн) и настройка инфраструктуры проекта (Vite, Tailwind, shadcn/ui).
*   **Этап 2 (Параллельно с этапом 2 бэкенда)**: Разработка API-клиента для взаимодействия с бэкендом. Создание базовых страниц личного кабинета и интеграция с API аутентификации.
*   **Этап 3 (Параллельно с этапом 3 бэкенда)**: Разработка всех страниц личного кабинета (управление товарами, генерация SEO и инфографики, отчеты). Разработка Landing Page.
*   **Этап 4 (Параллельно с этапом 4 бэкенда)**: Комплексное тестирование фронтенда (юнит-тесты, интеграционное тестирование с API, кросс-браузерное и нагрузочное тестирование).
*   **Этап 5 (Параллельно с этапом 5 бэкенда)**: Подготовка документации по фронтенду, финальная сборка и развертывание системы.
